# Рекомендации по продакшн-настройке Hermes Agent

## 1. Развёртывание Hermes  
Наиболее простой путь – установить Hermes в Python venv и запустить вручную, но для надёжности на продакшене предпочтительнее контейнеры или сервисы. Docker (или Docker Compose) даёт изоляцию и портативность: образ сам по себе без состояния, а конфигурацию и данные монтируют в volume, что позволяет обновлять образ без потери настроек【9†L61-L65】【14†L159-L161】. Официальная документация рекомендует Docker как «более универсальный вариант» для большинства случаев【14†L159-L161】. Если Docker не подходит, можно ставить через `pip` и управлять `systemd`-сервисом вручную – это даёт примерно тот же эффект управления сервисом. Важно запускать агент не от root, а от отдельного непривилегированного пользователя (например, `User=hermes` в systemd)【7†L226-L233】. VPS или домашний сервер – вопрос инфраструктуры: хватит ли постоянного питания и интернет-соединения; с точки зрения ПО они практически не отличаются. **Рекомендация:** на стабильной Linux-системе (Debian/Ubuntu LTS) поднять Hermes в Docker-контейнере и обеспечить автозапуск через systemd (`Restart=unless-stopped`), либо запустить из venv с созданием systemd-сервиса. Это даёт простоту обновления и автоматический рестарт при сбоях【14†L159-L161】【9†L61-L65】.

## 2. Стабильная работа 24/7  
Запускать Hermes как сервис рекомендуется через systemd или аналогичную систему. Например, unit-файл может содержать:  
```
ExecStart=/home/hermes/.local/bin/hermes gateway start
Restart=on-failure
RestartSec=10
StandardOutput=journal
StandardError=journal
User=hermes
...
ProtectSystem=strict
ProtectHome=read-only
NoNewPrivileges=yes
```
– `Restart=on-failure, RestartSec=10` обеспечивает автоматический перезапуск после падения с паузой, чтобы не перегружать LLM【7†L213-L220】. Параметры безопасности (`NoNewPrivileges`, `ProtectSystem`, `ProtectHome`) блокируют запись за пределами домашнего каталога агента【7†L226-L233】. После создания unit нужно выполнить `sudo systemctl daemon-reload; systemctl enable hermes; systemctl start hermes` для автозапуска при загрузке. Альтернативно можно воспользоваться встроенной командой: `hermes gateway install --system` создаст systemd-сервис для деамона【17†L401-L410】.  

Логи по умолчанию пишутся в journald. Смотреть их можно командами типа `journalctl -u hermes -f` или `journalctl -u hermes -p err --since "1 hour ago"`【7†L245-L253】. Для ротации и ограничения размера логов можно настроить `/etc/systemd/journald.conf` (например, `SystemMaxUse=200M`【7†L258-L266】). В `~/.hermes/logs/` также сохраняются логи TUI.  Для обеспечения «graceful restart» стоит добавить `TimeoutStopSec=60` (systemd подождёт до 60 секунд на завершение процессов)【15†L830-L839】. Таким образом после падений или перезагрузки Hermes автоматически поднимется, а журнал удобно фильтруется (`hermes logs`, `journalctl`).  

## 3. Безопасность  
**На уровне ОС:** всегда запускать Hermes не от root, а от выделенного пользователя с ограниченными правами【7†L226-L233】. Домашний каталог агента (`~/.hermes/`) и конфигурационные файлы (`config.yaml`, `.env`) нужно делать доступными только этому пользователю (chmod 600/700). SSH-доступ на сервер стоит жёстко ограничивать: использовать ключи вместо пароля, отключить логин root, включить 2FA по возможности. Входящие соединения стоит закрыть файрволом, разрешив только необходимые порты (например, 8642 для HTTP Gateway – но и его можно закрыть, если не нужен). В документации предупреждается, что «открывать любой порт на машине в интернете опасно»【9†L144-L147】. Ключи API и токены хранятся в `~/.hermes/.env`; этот файл тоже должен иметь права 600 и не попадать в общедоступные репозитории. Ни один компонент Hermes не требует root-прав, так что запуск от root потенциально даёт атакующему полный контроль над системой (это так же ограничивается настройками systemd【7†L226-L233】).  

**Внутри Hermes:** по умолчанию Hermes спросит одобрение перед исполнением опасных shell-команд (`approvals.mode: manual`)【28†L2153-L2162】. Никогда не ставьте `approvals.mode: off` (YOLO) в продакшене – это отключает все проверки и даёт агенту свободу выполнять любые команды【28†L2172-L2176】. Для дополнительной безопасности лучше использовать `tirith` (сканирование команд), встроенные блокировки опасных паттернов и настройки стека (config.yaml). Docker-бэкенд для терминала изолирует команды в контейнере, тогда опасные проверки вообще отключаются (контейнер сам выступает барьером)【21†L452-L456】. В `config.yaml` можно включить блокировку сайтов: раздел `security.website_blocklist` запрещает переход на опасные URL【28†L2123-L2130】. Также по умолчанию HTTP-браузер Hermes не разрешает переходы на локальные/внутренние адреса – это настраивается флагом `browser.allow_private_urls`. Наконец, потенциальные уязвимости в интеграциях (MCP, плагины) стоит оценивать отдельно: используйте только проверенные источники (официальные модули, Nous Portal и т.д.) и регулярно обновляйте через `hermes update` и `hermes skills audit`.  

## 4. Настройка Hermes  
Все конфигурационные файлы по умолчанию лежат в `~/.hermes/`【23†L61-L70】. Здесь `config.yaml` – основной файл с настройками (default-провайдеры, модели, инструменты, память, etc), а `.env` – для секретов (API-ключи, токены). Команда `hermes config set <ключ> <значение>` автоматически разносит параметры по нужным файлам (ключи/API токены – в `.env`, прочие – в `config.yaml`【23†L88-L92】【23†L105-L109】). Например:  
- `model.default` и связанные с ним поля (`provider`, `base_url`, `api_key`): выбирают LLM-провайдера. Можно использовать `hermes model` для настройки OAuth (Nous Portal)【26†L128-L131】.  
- `terminal.backend` (например `docker` или `local`): для изоляции команд. В продакшене рекомендуем `docker` (контейнер).  
- `memory.memory_enabled: true` и `memory.user_profile_enabled: true` по умолчанию включены【35†L730-L734】. Если не нужно – выключайте.  
- Настройки инструментов: можно глобально отключать наборы через `agent.disabled_toolsets` (например, `- memory` или `- web`【32†L794-L802】).  
- Параметры навыков (`skills.*`): любые специфические опции навыка (см. секцию 7). Например, `skills.guard_agent_created: true` заставит требовать одобрения, если агент сам изменяет навыки【37†L721-L725】.  
- **Обязательные**: хотя Hermes может работать «из коробки», обычно надо указать хотя бы провайдер LLM (или подтянуть Nous Portal). Остальные настройки можно оставить по умолчанию. Многие опции оптимальны «из коробки», не стоит без нужды снижать порог безопасности или резко наращивать ресурсы.  

Пример упрощённой конфигурации (`config.yaml`):
```yaml
model:
  default: anthropic/claude-opus-4
terminal:
  backend: docker
memory:
  memory_enabled: true
agent:
  disabled_toolsets: []
skills:
  guard_agent_created: true
```
А в `~/.hermes/.env` добавьте свои ключи:
```
OPENAI_API_KEY=...
NOUS_PORTAL_TOKEN=...
```
(всё секретное вне репозиториев, в файл с правами 600【23†L105-L109】). 

## 5. Голос (STT и TTS)  
Для распознавания речи (Speech-to-Text) Hermes может работать локально и в облаке. Рекомендуется установить `faster-whisper`: тогда голосовой ввод будет проходить офлайн без ключей【41†L162-L166】. Модель загружается при первом использовании (~150 МБ). Альтернативно можно использовать облачные сервисы: Groq Whisper (через ключ `GROQ_API_KEY`) или OpenAI Whisper (ключ `VOICE_TOOLS_OPENAI_KEY`)【41†L152-L156】. Groq дает бесплатный лимит запросов, OpenAI – платная схема. *Лучший локальный выбор:* **faster-whisper** – простой и бесплатный (privacy high). *Облачный выбор:* Groq (быстро, бесплатно до лимита) или OpenAI (качество выше, но дорого).  

Для синтеза речи (Text-to-Speech) Hermes поддерживает несколько поставщиков. По умолчанию включён **Edge TTS** (Microsoft Azure) – бесплатный, без ключа, качество «хорошее»【42†L75-L83】. Премиальные варианты: **ElevenLabs** и **Google Gemini TTS** – у обоих «отличное» качество, но платный (ElevenLabs полностью платный; Gemini даёт бесплатный лимит)【42†L75-L83】. Также есть локальные движки (NeuTTS, KittenTTS, Piper) – бесплатные, но качество «хорошее, но не выдающееся»【42†L75-L83】.  
- **Сравнение:** ElevenLabs/Gemini/XAI – выше всех по качеству, но с задержкой сети и затратами. Edge TTS – компромисс (достаточно естественный голос, бесплатный). NeuTTS и другие локальные – приватно, но могут требовать GPU.  
**Рекомендации:** *Локальный режим:* `faster-whisper` + Edge TTS (работает без ключей, латентность невелика)【41†L162-L166】【42†L75-L83】. *Облачный режим:* Groq Whisper + Gemini TTS (или ElevenLabs) для наилучшего качества. В большинстве случаев можно начать с локальных решений, а потом при необходимости добавить облачные аккаунты. 

## 6. Поиск, инструменты и интеграции  
Hermes умеет искать и взаимодействовать с веб:  
- **Веб-поиск:** инструмент `web_search` (и `web_extract` для содержания страниц) конфигурируется провайдерами. Рекомендуемый провайдер – **Firecrawl** (500 бесплатных запросов/мес с ключом)【43†L70-L79】. Если ключа нет, можно использовать бесплатные поисковики: **DuckDuckGo (DDGS)** или **Brave** (только поиск, без извлечения), а для парсинга контента по-прежнему Firecrawl или Tavily/Exa. Настройка удобна через `hermes tools` (раздел «Web Search & Extract»)【43†L154-L160】. Hermes автоматически суммирует большие страницы через вспомогательную модель («auxiliary.web_extract»), но при необходимости можно выключить суммаризацию и использовать `browser_navigate` для чистого скрапинга【43†L142-L150】.  
- **Браузер и Web API:** доступен toolset `browser_navigate/browser_snapshot`. Можно подключать облачные браузеры: **Browserbase**, **Browser Use**, **Firecrawl** предоставляют API для управления браузером в облаке【45†L62-L71】. В локальном режиме можно установить «agent-browser» и подключиться к своему Chrome/Brave (через CDP) для автоматизации сайтов. Hermes умеет автоматически переключаться: если страница локальная (localhost/интранет), то отдаст её на локальный браузер, иначе – в облако【45†L149-L158】.  
- **MCP (Model Context Protocol):** через MCP Hermes может обращаться к внешним сервисам и API. Например, можно установить и настроить MCP-сервер для GitHub, базы данных, Flow-автоматизации и т.д. Команды вида `hermes mcp install github` или `hermes mcp catalog` упрощают добавление этих интеграций【46†L45-L53】【46†L90-L99】. Важно: используйте готовые, одобренные интеграции (Nous поставляет «официальный каталог»), чтобы не запускать непроверенный код.  
- **Tool Gateway и Nous Portal:** подписка Nous Portal открывает доступ к большинству инструментов через единый API. Достаточно одного логина (`hermes setup --portal`) – и откроются web-search, browser, vision и другие инструменты без ваших ключей【41†L83-L87】【42†L75-L83】. Это очень удобно для начала.  
- **Социальные сети и мессенджеры:** отдельные адаптеры (Telegram, Discord и др.) подключаются через `hermes gateway` или `hermes setup <platform>`. Их настройка описана в документации по Messaging Gateway. Для мониторинга стоит сразу включить логирование gateway и убедиться, что боты аутентифицированы и получают обновления. 

## 7. Skills и расширение агента  
*Skills* – это «навыки» (скрипты/инструкции), которые агент может загружать по запросу. Все навыки хранятся в папке `~/.hermes/skills/`【50†L67-L70】. В ядре Hermes уже есть набор встроенных (они копируются при установке и обновляются командой `hermes update`, причём локальные правки сохраняются)【48†L72-L75】. Установленные навыки автоматически становятся доступными как slash-команды (`/название`), например `/github-pr-workflow create a PR ...`【50†L81-L90】. 

Для установки новых навыков используется CLI `hermes skills`. Например:  
```
hermes skills install official/security/1password
```
или из внешнего репозитория или по URL【52†L19-L28】. Навык будет скопирован в `~/.hermes/skills/<имя>`. Обновление навыка – `hermes skills update <имя>` (или просто `hermes skills update` для всех). Если выходят новые версии, команда `hermes skills check` покажет, что можно обновить. Удалить навык – `hermes skills uninstall <имя>`. Встроенные навыки можно «сбросить» к оригиналу через `hermes skills reset <имя> --restore`【48†L72-L75】【52†L43-L46】.

По поводу хранения в git: **рекомендуется сохранять конфигурацию (config.yaml, .env, SOUL.md) и собственные навыки в системе версионирования**, чтобы быстро восстановиться или отследить изменения. Удобно создать приватный репозиторий для `~/.hermes/config.yaml` и подпапки `skills/`, не включая секреты. Можно даже настроить «tap» – связку с GitHub-репо навыков (`hermes skills tap add owner/repo`)【52†L49-L54】. При переносе на новый сервер или утере – `hermes import` профиля/бэкапа или клонирование репозитория вернут всё. Команда `hermes skills snapshot export` позволяет экспортировать текущую конфигурацию навыков в JSON【52†L49-L54】. Таким образом workflow: правим навыки и конфиг локально, коммитим в git, а на сервере `git pull && hermes update` (или `import`) – и среда восстановлена.

## 8. Бэкапы и структура проекта  
Организуйте `HERMES_HOME` (обычно `~/.hermes/`) так, чтобы в нём хранились все нужные артефакты: `config.yaml`, `.env`, `skills/`, `memories/`, `sessions/`, `logs/`, `SOUL.md` и т.д.【23†L61-L70】. Практически полезно отделить код и данные: держать конфиг и навыки в одном месте (или репозитории), а проектные файлы (скрипты, подсказки) – рядом, например:  

```
~/hermes-config/      # или /opt/hermes/ – HERMES_HOME
    config.yaml
    .env
    skills/…
    memories/…
~/projects/           # ваши скрипты и контекст
    some-project/
        prompts/
        scripts/
```

Если нужно, переместите `HERMES_HOME` куда-либо (`export HERMES_HOME=...`) или делайте симлинки. Для резервного копирования можно пользоваться встроенной командой: `hermes backup` создаёт zip всего `~/.hermes`【58†L118-L122】 (включая настройки, память и историю). Восстановить из него – `hermes import backup.zip`. Альтернативно используйте профили: `hermes profile export имя -o archive.tar.gz` и `hermes profile import archive.tar.gz --name имя_новый`【59†L25-L28】. Git-репозиторий полезен для `config.yaml` и `skills/` (не храня секреты!). Скрипты проекта и собственные навыки лучше держать рядом с проектом и подключать через `tap` или внешние директории. При переносе между серверами достаточно развернуть Hermes (pip/docker), скопировать `HERMES_HOME` или распаковать бэкап, и запустить `hermes import` или `hermes update`. Регулярно делайте автоматические бэкапы (cron + `hermes backup`) и пушьте изменения конфигурации на внешний git для полной сохранности.

## 9. Мониторинг и отладка  
Для наблюдения используйте системные средства и собственные утилиты Hermes. Логи хранятся в journald и в файлах `~/.hermes/logs/`. Просмотр через `journalctl -u hermes -f` и `hermes logs` позволяет отслеживать ошибки: например, `hermes logs -f` ведёт live-tail основного лога, а `hermes logs --level WARNING --since 1h` покажет лишь ошибки за последний час【60†L19-L28】. Команда `hermes logs list` покажет ротацию логов. Для отладки конфигурации есть `hermes doctor` (проверяет конфиг и зависимости)【61†L7-L13】, а `hermes status` выдаёт общее состояние агента. Если агент перестал отвечать, проверяйте статус сервиса (`systemctl status hermes`) и журналы (`journalctl`). В критических случаях можно остановить `/ перезапустить сервис вручную. Плановой перезапуск (например, при обновлении) выполняйте через `systemctl restart hermes`.  

Проблемы с производительностью (утечки памяти, CPU) фиксируйте наблюдением процессов (`top`, Docker stats). Если замечаете постоянные падения, система самостоятельно перезапускает Hermes (из‑за `Restart=on-failure`). При серьезных сбоях возвращайте систему из бэкапа (`hermes import` или git) и включайте детальный режим логирования (`HERMES_LOG_LEVEL=debug`). Для быстрого оповещения можно настроить внешний мониторинг (напр. Monit/Sensu) на проверку активности сервиса или вывод `hermes status`. В большинстве случаев оперативно помогает просмотр логов и повторный запуск через systemd. 

## 10. Финальная рекомендация («Recommended Hermes Setup»)

В качестве **платформы** я бы выбрал стабильный Linux (например, Ubuntu LTS или Debian), установил Python 3.11+/Docker. Создал отдельного пользователя (`hermes`) и каталог (например `/opt/hermes/`), куда поместил бы конфиги и данные (или просто использовал `~/.hermes`). Сетевые службы (SSH, Telegram Bot API) – на стандартных портах, остальные закрыты файрволом. Затем установил Hermes Agent (через `pip` или Docker). Если Docker – запустил контейнер `nousresearch/hermes-agent` с монтированием `HERMES_HOME` и флагом `--restart unless-stopped`【9†L61-L65】. Если без Docker – создал systemd-сервис как выше и `systemctl enable`. В `/etc/default/hermes` можно определить переменные окружения (логирование, провайдер)【7†L279-L287】. 

Для **голоса** в личном использовании я бы сначала подключил `faster-whisper` (быстрое офлайн-STT) и Edge TTS (нетронутый Azure TTS, бесплатный). Это обеспечит базовую функциональность без затрат. Для **инструментов** рекомендую активировать Firecrawl (через Nous Portal или свой ключ) и включить Browserbase (или Firecrawl Browser) – по умолчанию они уже в Tool Gateway, если есть подписка. Дополнительно стоит добавить MCP-навык для GitHub (через `hermes mcp`), если планируются интеграции с репозиториями. 

**Бэкапы и миграция:** ежедневные синхронизации каталога `HERMES_HOME` (или автоматический `hermes backup`) в offsite-хранилище. В репозитории (Git) держите `config.yaml`, `.env` (но не публично) и собственные навыки. Используйте `hermes profile export/import` при переносе на новый сервер【59†L25-L28】. 

**Мониторинг:** полагаться на `systemd`+journald (таймауты и рестарты), а также на самоприложения Hermes (`hermes logs`, `hermes status`). Я бы настроил мониторинг самого процесса (например, через команду `systemctl is-active hermes`) и оповещения по email/Telegram, если сервис упал. 

**Итого:** мой личный setup – Ubuntu Server, пользователь _hermes_, Hermes в Docker под systemd. В `.env` – Nous Portal токен, ключи нужных API, включены faster-whisper и Edge-TTS. Поиск – через Firecrawl (Portal). Skills – только нужные, установленные `hermes skills install`. Регулярные `git commit` конфигов и `hermes backup` + автоматическое обновление. Такая система работает 24/7 без наблюдения и легко восстанавливается из бэкапа【58†L118-L122】【14†L159-L161】.

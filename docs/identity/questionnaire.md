# Анкета личности и памяти агента

Заполняй только устойчивые ответы. Временные задачи, текущие дедлайны и
одноразовые обстоятельства сюда не входят.

## 1. Личность ассистента → SOUL.md

1. Как зовут ассистента?
2. Какую роль он выполняет: секретарь, операционный партнёр, консультант,
   исследователь, наставник?
3. Какими тремя прилагательными должен описываться его характер?
4. Насколько прямо он должен возражать по шкале 1–5?
5. Насколько тёплым должен быть стиль по шкале 1–5?
6. Насколько формальным должен быть стиль по шкале 1–5?
7. Насколько подробными должны быть ответы по шкале 1–5?
8. Когда он должен действовать самостоятельно, а когда спрашивать?
9. Как он должен сообщать о неопределённости и недостатке данных?
10. Какие речевые привычки запрещены?
11. Приведи 3 примера хорошего ответа.
12. Приведи 3 примера плохого ответа.

## 2. Профиль пользователя → USER.md

1. Имя и предпочтительное обращение.
2. Язык и часовой пояс.
3. Основные роли: владелец бизнеса, специалист, студент, родитель и т.д.
4. Текущие долгосрочные цели.
5. Какой формат ответа удобнее?
6. Как давать критику и исправления?
7. Как пользователь принимает решения: быстро, через варианты, через данные?
8. Как устроен рабочий ритм и уровень энергии?
9. Какие ограничения повторяются постоянно?
10. Что раздражает в работе ассистентов?
11. Какие решения ассистент может принимать сам?
12. Какие действия всегда требуют подтверждения?

## 3. Среда и договорённости → MEMORY.md

1. Основная ОС, shell и рабочие устройства.
2. Главные репозитории, сервисы и рабочие пространства.
3. Какие системы являются источником истины?
4. Какие интеграции и MCP должны использоваться?
5. Какие технические обходные пути уже проверены?
6. Какие устойчивые правила безопасности действуют?
7. Какие регулярные процессы существуют?
8. Какие факты дорого или сложно обнаруживать заново?

## 4. Рабочие процедуры → Skills

Для каждой повторяемой процедуры:

1. Как пользователь формулирует такой запрос?
2. Какие источники данных нужны?
3. Какой порядок действий обязателен?
4. Какие операции изменяют данные и требуют подтверждения?
5. Как выглядит хороший результат?
6. Какие типовые ошибки нужно предотвращать?

## 5. Контекст клиента

Для клиентской установки дополнительно ответь:

1. От чьего имени говорит ассистент?
2. С кем он общается: владелец, команда, клиенты, подрядчики?
3. Какие темы конфиденциальны?
4. Какие утверждения нельзя делать без проверки?
5. Какие действия имеют юридические, финансовые или репутационные риски?
6. Какие каналы используются и отличается ли стиль между ними?
7. Как происходит эскалация человеку?
8. Кто утверждает изменения SOUL, USER, MEMORY и skills?

## Правило отбора

- В `SOUL.md` помещай только устойчивую идентичность и стиль.
- В `USER.md` помещай только компактные факты и предпочтения о человеке.
- В `MEMORY.md` помещай среду, договорённости и дорогие для повторного
  обнаружения факты.
- В skill помещай повторяемую процедуру.
- В `AGENTS.md` помещай правила конкретного репозитория.
- Для истории разговора используй `session_search`, а не постоянную память.

# Файлы агента: что за что отвечает и как их менять

Поведение агента Hermes складывается из нескольких файлов в `~/.hermes` клиента. У каждого
свой владелец, свой момент применения и свой способ правки. Ошибка в любом из них — либо
агент ведёт себя не так, либо утекает секрет, либо обрывается живой разговор клиента.

Проверено по коду Hermes 0.22.5 и на эталоне (`instances/healthy-student-vps.md`).

## Карта файлов

| Файл | Что определяет | Кто пишет | В git (наш репо) | Когда применяется | Как менять |
|---|---|---|---|---|---|
| `SOUL.md` | личность и **правила** агента — первый блок системного промпта | мы (наш блок) + клиент (своё) | эталон: [`soul-rules.md`](soul-rules.md) | **новые сессии**, перезапуск не нужен | правим блок между маркерами `<!-- hermes-setup rules vN -->`, бэкап `SOUL.md.bak-vN` |
| `config.yaml` | модель и провайдеры, MCP, подтверждения, инструменты по каналам, часовой пояс, cron | мы | нет (у каждого клиента свой) | частично сразу, частично после перезапуска gateway (см. ниже) | только `hermes config set …`, руками не редактировать |
| `.env` | **секреты**: ключи моделей, токены каналов, MCP | мы, по каналу клиента | **никогда** | после перезапуска gateway | только через stdin (плейбук 7.1), права 600 |
| `memories/MEMORY.md` | долгая память агента о пользователе | **агент сам** | нет | новые сессии | не перезаписывать; раз в месяц читать и удалять ошибочные факты |
| `skills/<категория>/<навык>/SKILL.md` | рецепты сценариев (сводка дня, планирование…) | мы | **да**: `skills/` | новые сессии / следующий запуск cron | правим в репо → `scp` на сервер → `hermes skills list` |
| `cron/jobs.json` | задачи по расписанию | Hermes | нет | сразу | только `hermes cron create/edit/pause/resume`, руками не трогать |
| `google_token.json`, `google_client_secret.json` | доступ к Google | мастер навыка | **никогда** | сразу | `setup.py`, после — `chmod 600` |
| `plugins/<имя>/` | сторонний код каналов (VK, MAX…) | автор плагина | нет (фиксируем коммит в карточке) | после перезапуска gateway | ставить только проверенный коммит |
| `.hermes.md` / `AGENTS.md` в рабочей папке | правила для конкретного проекта/папки | владелец проекта | в репо проекта | когда агент работает в этой папке | как обычный файл проекта |

### Что требует перезапуска gateway

| Изменение | Перезапуск |
|---|---|
| `SOUL.md`, навыки | не нужен — подхватят новые сессии |
| `approvals.*`, `cron.wrap_response` | не нужен — читается при каждом действии |
| `mcp_servers.*`, `providers.*`, `model.*`, `timezone`, `.env`, плагины | **нужен** |
| `hermes tools disable/enable --platform …` | новые сессии этого канала; для уверенности — перезапуск |

## Процесс изменения (каждый раз)

1. **Правка в репозитории**, не на сервере: шаблон правил (`soul-rules.md`), навык (`skills/…`),
   команда настройки — в плейбук. Примеры в шаблонах — вымышленные, без данных клиентов.
2. **Ревью**: что меняется в поведении агента и что клиент увидит иначе.
3. **Выкладка**: `scp` файла / `hermes config set …`. Для `SOUL.md` — бэкап и замена блока по маркерам,
   версия маркера +1.
4. **Перед перезапуском — проверка, что агент никого не обслуживает** (живой диалог или cron):
   ```bash
   grep -E "inbound message|response ready|Running job" ~/.hermes/logs/agent.log | tail -3
   ```
   Последний `inbound` без `response ready` после него — идёт разговор, **ждать**.
   Перезапуск обрывает ответ (на эталоне 02.11.2026 так оборвали задачу клиента).
5. **Проверка сценарием**: один реальный запрос в канале клиента или `hermes -z "…"`.
6. **Запись в карточку клиента** (`instances/<клиент>.md`): что, когда, какая версия правил.

## Тонкая настройка: скорость и токены (замерено 03–04.11.2026)

**Диагноз на эталоне (217 вызовов модели):** в среднем 78 тыс. токенов на вызов при ответе ~300 токенов;
даже первый вызов хода — 62 тыс. Причины:
1. Hermes **не сбрасывает разговоры в мессенджерах по таймеру** (убрано из ядра; есть плагин
   `hermes-session-reset-policy`), а сжатие по умолчанию срабатывает на 50% окна — у моделей с окном 1 млн
   это ~500 тыс. токенов, т.е. никогда. История VK-диалога росла до 241 тыс. токенов в одном вызове.
2. Уровень рассуждений `medium` на `glm-5.3-flash`: 2 353 токена «мыслей» и 19,7 с против 797 и 8,6 с на `low`.
3. Ответы MCP до 53 тыс. символов (выгрузка проектов Todoist целиком).

**Настройки (эталон):**

```bash
hermes config set model.default gemini/gemini-3.5-flash      # через Timeweb; см. сравнение ниже
hermes config set agent.reasoning_effort low                 # medium — только для сложного планирования
hermes config set fallback_providers '[{"provider":"timeweb","model":"zai/glm-5.3-flash"},{"provider":"regcloud","model":"glm-5.3-flash"}]'
hermes config set compression.threshold_tokens 32000         # сжимать историю при 32 тыс., а не при 50% окна
hermes config set compression.proactive_prune_tokens 20000   # без вызова модели обрезать старые выводы инструментов
hermes config set tool_budget.mcp_result_size_chars 15000    # потолок ответа одного MCP-вызова
```

Timeweb не возвращает `cached_tokens` (проверено) — кеширование промпта не учитывается, поэтому частое
сжатие истории ничего не «ломает» по деньгам.

**Сравнение моделей на реальном сценарии** «что у меня сегодня» (календарь + Todoist, только чтение, `low`):

| Модель (Timeweb) | Время | Результат |
|---|---|---|
| `zai/glm-5.3-flash` | 197 с | ✅ верно |
| `gemini/gemini-3.5-flash` | 24 с (36 с после всех настроек, включая старт сессии) | ✅ верно — **выбрана** |
| `openai/gpt-5.4-mini` | 21 с | ❌ показал календарь не за тот день |

После настроек: вызов модели 2–4 с при контексте ~20 тыс. токенов (было 20–60 с при 55–83 тыс.).
Цены моделей Timeweb в API и открытом доступе нет — сверять в личном кабинете перед выбором для клиента.

**Ещё не сделано:** отключение ненужных встроенных навыков (на эталоне 51 включён, стартовый промпт ~16 тыс.
токенов); сброс разговоров по простою (плагин) — пока не нужен, сжатие держит контекст.

## Как упаковать готового агента («профиль») — следующий шаг

Hermes умеет ставить **дистрибутив профиля** из git: `hermes profile install <git-url>`.
Дистрибутив владеет `SOUL.md`, `config.yaml`, `mcp.json`, `skills/`, `cron/` и манифестом
`distribution.yaml`; **не трогает** память, сессии, `.env` и авторизацию клиента; обязательные
секреты перечисляются в `.env.template`.

Это готовая упаковка для пресетов из исследования «профили 80/20»: один репозиторий = один
профиль («ассистент руководителя», «обработка заявок»…), ставится одной командой, обновляется
без потери памяти клиента. ⚠️ На эталоне ещё не проверено — первым шагом собрать текущую
конфигурацию эталона как дистрибутив и поставить её на чистый тестовый профиль.

## Формат ответа зависит от канала

Не все каналы показывают Markdown (VK — нет). Правила агента и навыки пишем под самый
бедный канал клиента: см. [реестр каналов](channels.md).

# Vault PARA Map

Use these established roots:

| Role | Folder | Decision |
|---|---|---|
| Capture | `0. Inbox/` | Unprocessed notes only |
| Projects | `1. Projects/` | Active outcome with an end condition |
| Areas | `2. Areas/` | Ongoing responsibility or standard |
| Resources | `3. Resources/` | Reusable topic or reference |
| Archive | `4. Archive/` | Inactive retained material |

Keep system content in place:

- `.obsidian/`: application configuration
- `_resources/`: attachments, templates, daily notes, scripts, and other
  support files
- `.git/` and `.backup/`: repository and backup internals

## Ambiguous Cases

- Course currently being completed: Project. Subject knowledge from the course:
  Resource. Ongoing education responsibility: Area.
- Active job search: Project. Career development: Area. Company research:
  Resource.
- Preparing for a race: Project. Maintaining fitness: Area. Training methods:
  Resource.
- Buying a specific item: Project if it requires meaningful research and has a
  defined finish; otherwise keep the reference shortlist in Resources.
- Person note: Resource unless it is only temporary project context.

## Inbox Review

For each note in `0. Inbox/`:

1. Read enough content to identify purpose and current actionability.
2. Rewrite an unclear title only when the intended meaning is evident.
3. Select an existing destination folder.
4. Flag duplicates, mixed notes, or uncertain ownership.
5. Present the proposed action before moving multiple notes.
